# Pre-mortem — Claude's independent pass (SEALED)

**Written:** 4 August 2026, before seeing the owner's list.
**Protocol:** KICKOFF-APP.md §C — two independent passes, owner first, second pass must not anchor
on the first. This file is written and closed *before* the owner is asked for his list, so
independence is verifiable from the file's timestamp rather than asserted.

**Inputs used:** KICKOFF-INPUT-lituk.md §C (empirical events from building v0, explicitly permitted),
v0's `README.md` and `index.html`, and direct measurement of `facts.js`. No knowledge of the owner's list.

**Prompt:** *It is six months later — 4 February 2027. This project failed spectacularly. Why?*

---

## C1. The readiness number was measuring option-shape recognition, not knowledge

The single measurable outcome in §B is "the proportion of the 410 facts he can answer correctly when
asked in a phrasing he has not seen before." Measurement of the deck shows the multiple-choice
options carry systematic tells:

| Tell | Measured | Chance |
|---|---|---|
| Correct answer is a **middle value** among four numeric options | **91.4%** (341 of 373 all-numeric forms) | 50% |
| Correct answer is the **longest** option | **40.2%** (301 of 749 forms with a unique longest) | 25% |
| Correct answer is the **shortest** option | 10.1% | ~25% |
| correctIndex position | 29.6 / 23.4 / 24.1 / 22.9% | 25% each |

Position is clean. Length and — devastatingly — numeric rank are not. A strategy of "pick a middle
number" scores ~91% on the 373 numeric forms while knowing nothing. This is an artifact of the
natural way to write plausible numeric distractors: bracket the true value above and below.

So the failure: v1 ships a readiness score computed from quiz performance, the score reads 90%+, and
it is substantially measuring a heuristic. He walks into Hammersmith confident against an exam whose
distractors were generated by someone else. **This is the worst risk on the list** — it is silent, it
inflates the exact number the project exists to move, it is present in the crown-jewel asset today,
and no amount of scheduler correctness touches it.

**Mitigation / tripwire:** (a) a CI statistical test over the deck asserting position, length-rank and
numeric-rank distributions sit within tolerance of chance — the build fails when a new form skews
them; (b) the readiness number is computed from **free-recall grades only**, never from MCQ answers,
so the tell cannot inflate it; (c) regenerate numeric distractors so the true value sits in every
rank position roughly equally.

## C2. Six weeks were spent re-achieving v0

v0 already does flashcards, quiz, SM-2 with five extensions, breadth gate, stats, timeline, offline,
Add-to-Home-Screen — in one HTML file, in daily use. v1's genuinely new value is three things:
the mistakes drill, the readiness signal, more question forms. The failure mode is that Next.js +
Vercel + Postgres + auth + migrations + design tokens + token lint + CI + gitleaks + Dependabot +
docs-consistency test + WCAG 2.2 AA consumes five of the six weeks, and the three things that
actually matter land in week six or get cut when the appetite expires. Six months later: a beautifully
engineered application that does what a single file did, minus the readiness answer he wanted.

**Mitigation / tripwire:** build the three thesis features first, against local storage behind a
repository seam; add the database only once they work. Hard tripwire: **if the mistakes drill and the
readiness number are not working by the end of week 3, the database is cut, not the features.**

## C3. Cross-device sync silently corrupted the schedule

If sync is last-write-wins over a serialised scheduler-state blob — the obvious implementation, and
what v0's `S.f` object invites — then studying on the phone (possibly offline, on a train) and later
opening the laptop overwrites the day's grades with stale state. SM-2 state degrades invisibly:
intervals look plausible, so nothing surfaces it. The one thing the database was bought for is the
thing that breaks. Compounded by free-tier Postgres cold starts: a 4-second wait on the sofa is the
difference between a ten-minute session and not opening the app.

**Mitigation / tripwire:** the source of truth is an **append-only review-event log** (fact id, form
index, grade, client timestamp); scheduler state is *derived* by replaying events, never stored as the
authority. Sync becomes event upload and merge, which is commutative and cannot lose a grade. Test:
replay the same event set in shuffled order and assert byte-identical derived state.

## C4. The readiness number was built to reassure, and so it lied

"Am I ready?" is the hardest thing in this project and the easiest to fudge. A number defined as
"% of facts with interval ≥ 21 days" only ever goes up, reads 94% while the twelve unverified facts
are still wrong and while negatively-framed material has never been tested, and he believes it.
§What-v1-must-do already names this — "a percentage that only ever goes up is worse than nothing" —
which means the risk is that we design the *widget* before the *meaning* and then rationalise.

**Mitigation / tripwire:** define the number before designing its presentation; require by construction
that it **can go down** (time decay, and lapses reducing it); calibrate it at least twice against an
external check — a full mock exam at lifeintheuktestweb.co.uk — with the mock score written down as a
number next to the app's prediction. If the app says 90% and the mock says 70%, the model is wrong and
gets changed. A readiness model that is never calibrated against reality is decoration.

## C5. A wrong fact shipped and was drilled to permanence

12 facts are flagged amber today and unresolved. The trap is sharper than "content might be stale":
**the examinable answer is the handbook's, even where the handbook is now factually wrong.** So both
drift *and* over-correction are failure modes — someone helpfully updating the Council of Europe
membership or the monarch to today's truth introduces an error, and it looks like a fix. Spaced
repetition then does its job perfectly and burns the wrong fact in permanently. Repetition is what
makes this expensive here: a wrong fact drilled twenty times is harder to remove than one never seen.

**Mitigation / tripwire:** a `source` field per fact naming handbook edition + page; CI fails while any
fact still carries an unresolved verify flag past a stated due date; the 12 are resolved against the
printed book as a gated task before v1 is used in anger, and the resolution logged. Postmortem trigger
already declared in §H — keep it.

## C6. The scheduler was rewritten and quietly regressed

v0's five additions interact: post-lapse resume × breadth gate × leech taper × fuzz × relearn step.
A TypeScript rewrite with a relational store changes ordering, rounding and tie-breaks. §C4 of the
input file states the empirical version of this — an interval that quietly clamps to 1 day is
invisible to code review. Six months later he is over-reviewing settled material and under-reviewing
weak material, and the app feels fine.

**Mitigation / tripwire:** port the 60-day simulation into CI **before** the rewrite, running against
v0's algorithm, to establish a golden baseline; v1 must reproduce v0's aggregate load curve within
tolerance. Assert invariants every run: no interval ever violates the breadth gate; the queue always
drains; every fact is reachable; no fact's due date moves backwards without a lapse.

## C7. Free practice ate the schedule

Live question, not settled — so a live risk. If on-demand practice writes grades to the scheduler, one
long evening pushes 200 facts out to long intervals on the back of recognition-mode answers, the real
queue empties, and the app reports "nothing due" for a week. Failure state looks exactly like success.

**Mitigation / tripwire:** whatever is decided, one invariant holds and is tested — **a free-practice
session can never increase a fact's due date.** It may shorten it. That single assertion makes the
worst version of this impossible regardless of which option is chosen.

## C8. Cards-only usage left 49 facts permanently gate-locked

Measured, not hypothesised. 6 facts have exactly one recall-usable (non-`mcqOnly`) form; 43 have two.
`pickForm(i,'recall')` restricts to non-mcqOnly forms, and `breadth()` counts distinct forms answered
correctly. So a user who drills mainly in **Cards** can never raise those 6 facts above breadth 1 —
permanently capped at 6 days, resurfacing forever — and can never take the 43 past breadth 2, capped
at 30 days. 49 facts, 12% of the deck, cannot fully graduate through Cards alone. From the inside it
reads as "I keep failing these," which is demoralising and false.

Affected: facts 17, 218, 222, 223, 357, 367.

**Mitigation / tripwire:** content rule enforced in CI — every fact carries ≥2 recall-usable forms —
or the breadth gate counts against forms reachable in the mode actually being used. Either way it is
a test, not a note.

## C9. The process outgrew the product

The kit prescribes ~10 living docs, a ledger, a docs-consistency test, CI, pre-push hooks, Dependabot,
branch protection, design tokens with lint enforcement, four audit skills and a launch gate — for a
**single-user study app with an eight-week useful life and no third-party data.** Applied without
judgement, the repo ends up majority process, sessions are spent reconciling documents, and the
appetite is consumed by ceremony. Applied by silently skipping parts, `/jorge-drift-check` reports
drift every run and the signal is lost.

**Mitigation / tripwire:** scale the kit deliberately and *in writing* in the BRIEF — name which parts
are in, which are consciously waived and why, as a logged decision. Waived-by-decision is clean;
skipped-in-silence is drift.

## C10. It outlived its purpose and became a hobby

He passes on 25 September 2026. The app's job is finished. Either v1 is unfinished and the motivation
to complete it drops to zero — a half-built app on top of a working v0 — or, worse, the building was
always the more enjoyable half and the six-week appetite becomes six months of a tool nobody needs.
§D already says "it is explicitly fine for this to be a product that stops being needed," which is the
right instinct and also exactly the sentence that gets forgotten.

**Mitigation / tripwire:** declare now what happens on 26 September 2026 — archive, or continue with a
new stated purpose logged as a decision. Put the date in the BRIEF. Appetite expiry is a hard stop.

## C11. Single-user auth became a single point of failure

A magic-link provider on a free tier is a third-party dependency. If it changes terms, rate-limits, or
its email lands in spam three weeks before the exam, he is locked out of his own study tool with no
recovery path — and the data is in a database he cannot reach from the sofa.

**Mitigation / tripwire:** auth behind an adapter seam (already in §D), plus a **local-only escape
hatch that works with no network and no login** — the app must remain usable read/write offline on the
phone even if every service is down. Test: airplane mode, cold load from Home Screen, complete a
session, sync later.

## C12. Duplicate facts drilled as two separate schedules

Measured: facts 193 and 352 carry the identical question and identical answer ("The Scottish Parliament
and the Welsh Assembly first met in which year" — 1999). Two independent SM-2 schedules for one piece
of knowledge; review load slightly inflated, and the readiness denominator is wrong by one. Also facts
205 and 206 share the stem "Which of these is one of the fundamental principles of British life" with
*different* correct answers and `mcqOnly=0`, so both are served as free-recall cards where several
answers are legitimately correct — he will mark himself wrong for being right.

**Mitigation / tripwire:** CI check for duplicate canonical questions and for duplicate form stems
across facts; a shared stem with differing correct answers must be `mcqOnly`, enforced.

## Ranking, if only six survive the merge

1. **C1** — the metric is compromised at source. Everything else assumes the number means something.
2. **C2** — the appetite is the scarcest resource and the default path spends it on scaffolding.
3. **C4** — a dishonest readiness signal is the one output that can send him into the exam wrong.
4. **C5** — content errors are unrecoverable once drilled, and the correction is counter-intuitive.
5. **C6** — a silent scheduler regression invalidates the daily practice without any symptom.
6. **C3** — sync is the sole justification for the database; if it loses data it is worse than none.

C7, C8, C12 are cheap to convert into CI assertions and should become tests rather than risk rows.
C9, C10, C11 are governance and belong in the BRIEF as declarations with dates.
